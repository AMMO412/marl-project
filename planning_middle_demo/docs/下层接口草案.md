# 中间层与下层的接口草案

本文是**普通任务仿真接口讨论稿**，尚未获上下游确认。我们负责任务规划中间层及其适配；其他团队负责 Gazebo、UE5、底层移动及任务执行能力。本文不包含运动控制器，也不设计具体作战行动。

## 责任边界

```text
上层：任务与成员输入
    ↓
我方：输入适配 → 规则流程 → 指令版本与状态 → 反馈判定 → 日志
    ↓ 任务级协议（拟议，尚未连接）
下层：接收与执行、结果上报
    ↓ 当前已有的速度/位姿链路
Gazebo 与 UE5（其他团队）
```

目前对方只提供速度与位姿接口，任务级接收、执行、取消和结果协议还没有。因此这里是一项**需要双方对齐的接口空缺**，不是我方已经实现、也不是自动归属我方的导航工作。

## 先统一的约定

| 内容 | 本目录当前约定 | 正式接入前还需什么 |
| --- | --- | --- |
| 消息版本 | `middle-demo/v1`，仅工位沙盒 | 真实任务语义应另定版本，不能在原版本中悄悄改变单位或成功含义 |
| 身份 | run_id、plan_id、command_id、job_id、worker_id、attempt | 真实逻辑平台 ID 与仿真模型 ID 的显式对应；不得按编号随意加一 |
| 时间 | 演示整数仿真秒；字段明确带 sim_s | 统一时钟来源、精度、重置标识和接收端时间戳 |
| 单位 | 普通工位 duration_s；参考参数使用 m/s、kg、s 等明确名称 | 真实位置使用米、角度使用弧度，先确认模型坐标变换 |
| 位姿 | 当前沙盒不产生位姿 | 真实反馈应带 frame_id、仿真发生时间和明确的 x/y/z、姿态语义 |
| 缺数据 | 未收到反馈保持原状态；未知能力为 null | 明确哪些字段来自实测、仿真真值、估计或人工配置 |
| 取消 | 请求取消后占用仍保留，收到结束结果才释放 | 执行端取消语义、超时及重启恢复策略；不能把消息送达当作实际停止 |

尽量保持消息外壳稳定，任务内容放在独立定义中。新增坐标、时间窗或成果类型前先改契约与样例；协议并未冻结为真实项目标准，也不能承诺任何业务语义变化都只改适配器。

## 本目录实际交换的消息

`Coordinator.plan(now)` 返回 JSON 可序列化的消息列表。每条消息包含 `protocol/run_id/plan_id/clock/command`，command 为：

```json
{
  "command_id": "demo:J01:1",
  "job_id": "J01",
  "worker_id": "worker-A",
  "attempt": 1,
  "issued_sim_s": 0,
  "expected_end_sim_s": 2,
  "action": "start",
  "target_command_id": null
}
```

取消消息使用独立 command_id，`action=cancel`，target_command_id 指向原指令。下层取消反馈仍关联原执行尝试，避免把取消请求本身当成一个新作业。

`MockPeer.submit(messages, now)` 返回接收或取消反馈；`MockPeer.poll(now)` 返回进度和结果。两者都是模拟函数，没有网络或 ROS 通信。反馈示例：

```json
{
  "protocol": "middle-demo/v1",
  "run_id": "demo",
  "event_id": "mock:4",
  "command_id": "demo:J01:1",
  "job_id": "J01",
  "worker_id": "worker-A",
  "attempt": 1,
  "sim_s": 2,
  "status": "succeeded",
  "progress": 2
}
```

status 可为 accepted、progress、succeeded、failed、cancelled。这里的 progress 仅是工位模型的处理秒数，结果由替身产生，不冒充传感器成果。该消息不是 Twist，也不能直接发送给当前 cmd_vel 话题。

## 对方现有接口必须保留的事实

依据项目 `资料/接口说明/机器人移动话题说明.md`（相对本文件为 `../../资料/接口说明/机器人移动话题说明.md`），尚未独立联调：

| 类型 | 文档编号 | 控制 / 位姿话题 | 代理方式 |
| --- | --- | --- | --- |
| UGV | 01–20 | `/container_00/robot_XXX` / `/model/robot_XXX/pose` | 地面差速 |
| TANK | 21–30 | 同一命名规则 | 地面差速外观代理 |
| PLANE | 31–40 | 同一命名规则 | 关闭重力的速度代理 |
| WING | 41–50 | 同一命名规则 | 关闭重力的速度代理 |

控制为 geometry_msgs/msg/Twist，反馈为 tf2_msgs/msg/TFMessage。Twist 不包含目标、时间戳、任务 ID 或执行结果，不能把上述任务外壳直接塞进去。位姿 frame 元数据含私有延迟信息，不能不经解析就当标准 TF 树。

常用发令频率约 20 Hz，不等于反馈频率或时间同步精度。发布器退出并不保证停止。当前说明没有电量、载荷、任务成果或完整任务取消确认来源；不能由位姿替它们补写成功。

## 公开参数的采用方式

`config/platform_references.json` 登记四类结构；公开参考值、当前场景限值是两个对象。现在规则沙盒只处理工单，不读取物理参数做分配，也不据此控制机器人。

| 类别 | 本次可登记的公开资料 | 当前限制 |
| --- | --- | --- |
| UGV | Husky A200 科研平台的质量、最大速度、两种载荷工况、平均运行时间 | 不等于当前无人车模型；最大载荷和全地形载荷不混用 |
| TANK | 文档的差速代理类型与号段 | 未确定对应公开代理模型；不将实车厂家性能绑定到当前外观 |
| PLANE | PX4 rc_cessna 的 base_link 质量 1.5 kg | 不是整机质量；不足以给出速度、续航或载荷能力 |
| WING | ArduPilot Zephyr 的 wing link 质量 1.5 kg | 不是整机质量；当前代理与上游模型是否同源未知 |

Husky 官方手册同时列最大载荷 75 kg、全地形载荷 20 kg、最大速度 1 m/s、平均运行 3 h，这些工况需随参数保留。[Husky A200 官方手册](https://docs.clearpathrobotics.com/docs_robots/outdoor_robots/husky/a200/user_manual_husky/)。两种飞机 link 数值来自 [PX4 模型](https://github.com/PX4/PX4-gazebo-models/blob/main/models/rc_cessna/model.sdf) 与 [Zephyr 模型](https://github.com/ArduPilot/ardupilot_gazebo/blob/main/models/zephyr/model.sdf)，main 分支可变化，后续采用具体模型时应固定提交版本。

这份调研对接口与参数语义有用，不能直接替代四类平台完整、已校准的能力表。当前未引入武器性能、打击效能或战术分配参数。

## 下一次对接先要什么

1. 对方实际 roster 一份，逐项对齐平台 ID、类型、控制话题与位姿话题；本文号段只来自说明。
2. 一条真实位姿样例、仿真时钟样例及坐标系解释，核对私有 frame 元数据。
3. 任务级执行模块由谁提供；如果仍只有速度接口，明确临时执行适配的负责人和边界。
4. 对方可提供的 accepted/progress/result/cancel 等真实反馈样例；没有的能力明确返回不支持。
5. 区分公开参考参数、已配置模型参数与验证值；先确认本阶段实际需要的项，不以补齐全部指标阻塞规则演示。
