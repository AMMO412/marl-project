# 融合规划与执行工作台

当前主程序在 `planning_middle_demo/`：统一接口、任务分配、行为执行、本地运动模拟、浏览器工作台与全链路追溯共用同一条运行链。本文是工程唯一入口，核对日期为 2026-11-16。

## 启动与使用

在 Windows 双击根目录 **`启动工作台.cmd`**，按终端显示的地址打开浏览器。默认端口为 8766，占用时自动顺延；旧页面连接的服务不会随源码更新自动重启。

也可在工程根目录运行：

```powershell
py -3 -X utf8 planning_middle_demo/workbench_server.py --open --open-path '/?new=interop'
```

浏览器工作台只需本机 Python 标准库，不需要 npm、WSL 或 WebView2。C# 原生桌面保留兼容入口 `desktop_app/dist/MARL界面预览.exe`，构建说明见 [桌面端 README](desktop_app/README.md)。根目录旧的“启动软件.cmd”“打开场景工作台.cmd”当前不存在，不再作为启动方法。

1. 新建运行：选任务场景、地图、优化目标与运行上限；按需编辑任务、平台、目标和威胁区。任务场景包含五类演示、复杂算法测试及综合案例，实际目录以工作台下拉框为准。
2. 地图默认采用全局分配视图，运动中的智能体显示最近 10 秒拖尾；可聚焦任务/成员、打开完整轨迹、查看高度和实际路径。动作流程图与空间地图分开解释。
3. 勾选实时演示后可暂停仿真、修改未完成内容并继续；“结束本轮并保存”在暂停状态也可用。保存的是部分执行结果，不把未完成任务改成成功；保存结束或异常退出后可新建。
4. 历史回放可暂停查看；中途编辑续算会保留原运行编号和旧版本，完成项锁定。初始配置另建运行不会覆盖原始输入。
5. 报告、输出文件和追溯页都绑定所选运行编号。ROS2 导出优先读取同目录完整运动序列，兼容静态计划。

内置城市地图同时用于规划和显示。随机生成的任务区域与威胁区尽量分散、避免重合，并保留远端任务候选；几何校验和分配成功仍不等于执行成功。对比算法需使用相同地图、输入快照与种子，不能比较不同随机题目的结果。

## 运行结果保存位置

| 位置 | 用途 |
| --- | --- |
| `desktop_app/dist/data/runs/` | 当前本机工作台的默认运行记录；包含原始输入、请求、报告、轨迹、运动导出和追溯归档 |
| `planning_middle_demo/outputs/` | 历史/命令行运行及专项诊断；默认目录不存在时工作台也回退到这里 |

## 当前能力与边界

五类任务已接入统一规划及本地行为链。可拆分的侦察/巡逻席位支持编组内局部替补，其他成员保持原指令；无合格替补或整组协同任务回到整任务重排。配置变更消解率统计 20 个调度回合内得到已采纳反馈的实际子任务切换，无样本显示“—”，不当作 100%。

规划与运动层保留空地障碍作用域、高于低建筑时越障、对空威胁避让、驻点/返航、运动限幅、路径平滑和有界缓存。计划、执行采样、模拟效果判定及完整归档属于不同证据，不能互相替代。

目前主要是本地 `mock_only` 运行与二维回放；独立 ROS2 节点的离线检查不代表定位闭环、Gazebo/UE5 或真实平台联调完成。正式验收与外部接口确认仍待补齐。
