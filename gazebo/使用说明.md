# Gazebo 场景预览与运动

先双击 `打开Gazebo预览.cmd`，首次载入建筑和地形约需30–60秒。窗口出现草地和机器人后再操作。

1. 双击 `移动1号机器人.cmd`：1号车以0.5米/秒指令前进10个墙钟秒，结束后重复发送零速度。仿真慢于实时，不能据此推算一定移动5米。
2. 双击 `停止1号机器人.cmd`：打断正在运行的移动脚本，并发送停车指令，无需等待10秒结束。
3. 双击 `查看场景全貌.cmd`：切换远景，看道路、建筑、湿地和山地。
4. 双击 `回到机器人近景.cmd`：回到初始机器人编队的视角。可在右侧实体树找到 `robot_001` 并右键选择移动镜头到该对象。
5. 用完双击 `关闭Gazebo预览.cmd`：同时关闭本预览的服务和窗口。仅关闭窗口时，后台物理仿真仍会运行。

这是基于下载包模型资源、使用本机 WSL Ubuntu / Gazebo Jetty 10.5 的独立适配预览。原包在 `GazeboUE-single-container-v1/`，保持原样；衍生场景、脚本和记录在 `local_preview/`。不用Docker、ROS或UE即可查看和发送底层运动指令；尚未接入项目的集合/检查点控制器，不会自动执行任务。

## 为什么不能直接双击原SDF

原SDF包含另一台机器的绝对网格路径、旧版插件名和自定义位姿插件路径；外部模型还需要资源搜索目录。预览生成器修正这些路径和插件名，使用已安装的标准PosePublisher。50台统一为 `robot_001` 至 `robot_050`，直接通过Gazebo Transport发布 `/robot_001/cmd_vel`，并读取 `/model/robot_001/pose`。

本机Ogre2地形着色器编译失败，预览改用已安装的Ogre1。山体外观从包内257×257的16位高程图转换为OBJ；山体物理碰撞仍保留原高程图。此适配不保证与UE画面的材质和植被效果一致，不代表已验证全地图导航或碰撞安全。

## 命令入口

在工程根目录的PowerShell中：

```powershell
wsl -d Ubuntu -- /usr/bin/python3 /mnt/d/Desktop/MARL项目/gazebo/local_preview/preview.py open
wsl -d Ubuntu -- /usr/bin/python3 /mnt/d/Desktop/MARL项目/gazebo/local_preview/preview.py drive --robot 1 --linear 0.5 --seconds 10
wsl -d Ubuntu -- /usr/bin/python3 /mnt/d/Desktop/MARL项目/gazebo/local_preview/preview.py view --view overview
wsl -d Ubuntu -- /usr/bin/python3 /mnt/d/Desktop/MARL项目/gazebo/local_preview/preview.py close
```

修改机器人编号可控制其他机器人；当前工具只提供前进/偏航，不提供自动导航、避障或飞行控制。地面机器人编号1–30。

`local_preview/runtime/server.log` 和 `gui.log` 为启动日志；每轮运动生成独立的 `drive_*.json`，包含真实Gazebo位姿样本、位移和停车后漂移量。

Windows双击入口使用ASCII内容和CRLF换行，经 `local_preview/launch.py` 自动解析当前目录的WSL路径；不再依赖批处理文件中的中文编码。启动窗口会等待实际渲染帧，并在失败时保留错误。每次双击另存 `local_preview/runtime/launch_*.log`，方便检查哪一步失败。

重新生成山体外观（仅资源丢失或需要重建时，使用Windows已有Pillow）：

```powershell
py -3 gazebo/local_preview/make_terrain_mesh.py
```

## 原版Docker服务

原版使用ROS 2 Jazzy + Gazebo Harmonic，默认无图形窗口。需要启动Docker Desktop的Linux引擎，再进入 `GazeboUE-single-container-v1/` 执行 `docker compose -f compose.single.yaml up -d --build`。本次本地预览不代表Docker容器或ROS桥接已经验证；详见包内 `SINGLE-CONTAINER-DEPLOY.md`。
