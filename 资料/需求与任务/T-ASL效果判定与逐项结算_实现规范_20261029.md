## 0. 范围决策（用户已确认）

1. **工作台默认演示**：asl_city（左侧十字路口建筑群）；多任务记录保留下拉可选。
2. **效果判定**：毁伤 / 压制 / 夺占 三分类全部建模；评估走可插拔接口，默认桩实现并显式标注"未验证"。
3. **终止与结算**：弹药耗尽、超时 → 终止且不计成功；结果项逐项存 达成/未达成/待确认；目标消失、被迫撤离只留接口字段不实现。
4. **兵力**：本轮只加**评估组**（独立评估单元）；压制组/掩护组/队形/通信拓扑/ROE 下轮。

## 1. 事实模型（不变量）

- 指令发送、平台到位、动作结束、效果达成是**四个不同事实**，各有独立事件与时间戳，不得互相冒充：`command_received` / `all_staged` / `assault_started` / `effect_achieved`。
- 评估是第五个事实：`assessment_requested`（评估发起）→ `assessment_received`（评估回传）→ `confirmed`（确认）。
- 评估结果必须绑定 **本任务(job_id) + 本对象(target_id) + 当前执行版本(attempt)**；桩判定结果同样携带三者。
- 预测不代替确认：不引入概率分配；单次结果只由评估接口出。

## 2. 效果三分类

### 2.1 毁伤 damage
- 主成功标准：毁伤等级 ≥ `required_level`。
- 模型：执行期每 `fire_interval` 一轮齐射；每平台每轮 `rounds_per_salvo` 发、每平台总弹 `ammo`；占位在 `objective_radius` 内且弹药 > 0 即视为命中（演示口径，桩判定）；每命中加 `damage_per_hit`。
- 辅助指标：命中率 = 命中/发射、弹药消耗、二次打击（一轮齐射后等级不足 → `restrike_needed` 事件）。
- 判定依据：评估接口按开火日志累计等级。

### 2.2 压制 suppress
- 主成功标准：**连续**压制时长 ≥ `required_duration`（中断超过 `recovery_gap` 则覆盖时段断开、连续时长重计）。
- 模型：任一突击成员在射程内开火 → 目标被压制；无人开火即中断。
- 辅助指标：火力覆盖总时长、目标恢复时间（末次开火后判定恢复）、我方损失（桩：不模拟）。
- 判定依据：评估接口按开火日志判覆盖区间。

### 2.3 夺占 seize
- 主成功标准：控制权建立后保持 ≥ `required_control_s`。
- 模型：≥ `min_occupants` 名成员进入 `objective_radius` → `control_established`；跌破 → `control_lost`；连续控制时长 ≥ 要求 → 夺占达成。
- **移交后坚守分别结算**：夺占达成后 `handover` 移交，坚守 `hold_required_s`；"夺占"与"移交后坚守"是两个独立结果项，夺占成功不自动使坚守成功。
- 辅助指标：控制时长、敌方反击次数（桩：0）、移交时间。

## 3. 评估接口（可插拔）

- 新模块 `planning_middle_demo/assessment.py`：
  - 协议 `Adjudicator.adjudicate(task_ref, evidence) -> Adjudication`
  - `task_ref` = {job_id, target_id, attempt, effect_kind, params}
  - `evidence` = 事件时间线、开火日志、覆盖区间、控制区间、成员位姿摘要
  - `Adjudication` = {items:[{id,status,metric,evidence_ref}], overall, adjudicator, verified}
- 默认实现 `StubAdjudicator`：按 evidence 的**确定性规则**判定（不掷随机数）；`verified=false`，一切输出标注"桩判定·未验证"。
- 真实外部裁决接入：实现同协议替换即可（HTTP 回调形态仅预留说明，本轮不实现）。

## 4. 终止条件（只有达到规定效果才计为成功）

- **弹药耗尽**：全体可开火成员弹药 = 0 且效果未达成 → `terminate(ammo_exhausted)`，作业 failed。
- **超时（两类截止分别核验）**：
  - 执行截止 `execute_deadline`：效果未达成而截止到 → `terminate(deadline_exceeded)`，failed；
  - 确认截止 `confirmation_deadline`：效果达成但评估未回传而截止到 → "确认"结果项未达成（超时未确认），overall 不计成功。
- **时间窗**：效果达成须在 `window` 内，越窗 → "时间窗"结果项未达成。
- **预留不触发**：`target_vanish`、`forced_withdraw`（事件种类与配置字段先行，判定逻辑留接口）。

## 5. 逐项结算

- 每作业 `result.items[]`：`{id, label, status: achieved|failed|pending, t, evidence}`。
  - 必需项：规定效果、时间窗、（夺占时）移交后坚守；
  - 信息项（不计成败）：弹药消耗、命中率/覆盖时长/控制时长、二次打击次数。
- overall 规则：全部必需项 achieved → succeeded；任一 failed → failed（附终止原因）；有 pending 且未到确认截止 → pending；确认截止后仍 pending → failed。
- **部分达成不得冒充全部成功**：report.json 与工作台均逐项展示，overall 单独一栏。

## 6. 兵力编成（asl_city，6 台）

- `rover_01` 侦察指示组（信息保障）：机动期先到观察位，出 `target_designated`。
- `rover_02–05` 突击组：分进集结 → 执行（开火/占位）。
- `rover_06` 评估组：随队机动，执行期前出评估观察位 `assessment_post`；`assessment_requested` 由其在位发起，`assessment_delay` 后经评估接口出结果并回传。
- 续航闸门口径同步：评估组里程 = 起点→集结→评估位→撤离（`_behavior_mileage` 认评估角色）。

## 8. 验收（测试）

1. 毁伤·成功：等级达标、窗内、确认回传 → succeeded，items 全 achieved。
2. 毁伤·弹药耗尽终止：弹药不足以达标 → failed，termination=ammo_exhausted。
3. 毁伤·超时终止：execute_deadline 前未达标 → failed，termination=deadline_exceeded。
4. 确认超时：assessment_delay > confirmation_deadline → 确认项未达成，overall 非 succeeded。
5. 压制·成功：连续覆盖达标；中断重计有专门用例。
6. 夺占·分别结算：夺占 achieved + 移交后坚守 failed → overall 非 succeeded（两独立项）。
7. 逐项结构：效果 achieved + 时间窗 failed → overall failed（部分不冒充）。
8. 评估组在场，assessment_received 归属评估单元；桩标注 verified=false。
9. 既有 97 项回归全过（编成变更涉及的用例同步修正）。
10. 工作台默认运行为 asl_city。
