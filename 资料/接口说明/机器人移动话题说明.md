# 机器人移动话题说明

适用工程：GazeboUEBridge 当前 50 台混合机器人场景。本文依据本地场景生成器、ROS bridge 启动脚本及控制脚本整理。

## 1. 四类机器人的控制话题

所有移动命令均使用 ROS 2 消息类型 **`geometry_msgs/msg/Twist`**，每台机器人独立订阅一个 `cmd_vel` 话题。

| 机器人类型 | 数量 | 编号 | ROS 2 移动话题范围 | 示例 |
|---|---:|---|---|---|
| 无人车 UGV | 20 | 01–20 | `/rover_01/cmd_vel` 至 `/rover_20/cmd_vel` | 1 号：`/rover_01/cmd_vel` |
| 无人坦克 TANK | 10 | 21–30 | `/rover_21/cmd_vel` 至 `/rover_30/cmd_vel` | 21 号：`/rover_21/cmd_vel` |
| 常规布局固定翼 PLANE | 10 | 31–40 | `/rover_31/cmd_vel` 至 `/rover_40/cmd_vel` | 31 号：`/rover_31/cmd_vel` |
| Zephyr 飞翼 WING | 10 | 41–50 | `/rover_41/cmd_vel` 至 `/rover_50/cmd_vel` | 41 号：`/rover_41/cmd_vel` |

**编号不足两位时补零。** 为兼容原来的控制接口，飞机、坦克的内部名称仍以 `rover_` 开头。当前没有单独的 `/tank_XX/cmd_vel` 或 `/plane_XX/cmd_vel`。上述范围代表每台一个话题，不是广播或通配符话题。

## 2. 指令如何到达机器人

```text
Windows PowerShell（调用 WSL）或 WSL 中的 Python/C++ ROS 2 节点
  → /rover_XX/cmd_vel [geometry_msgs/msg/Twist]
  → ros_gz_bridge（ROS 2 → Gazebo）
  → /rover_XX/cmd_vel [ignition.msgs.Twist]
  → Gazebo 控制插件
  → 机器人运动
  → 位姿回传并同步到 UE5
```

ROS 2 和 Gazebo Transport 两侧话题同名，但消息类型不同，由桥接程序转换。应用程序通常只需向 ROS 2 一侧发布命令；UE5 接收位姿用于显示，不是本项目的运动控制入口。

## 3. 移动字段与单位

| Twist 字段 | 无人车 01–20 | 坦克 21–30 | 两类飞机 31–50 | 单位 |
|---|---|---|---|---|
| `linear.x` | 前进/后退 | 前进/后退 | 简化前进/后退 | m/s |
| `angular.z` | 左转/右转 | 左转/右转 | 简化偏航转向 | rad/s |
| `linear.z` | 不支持 | 不支持 | 简化上升/下降 | m/s |
| `linear.y` | 保持 0 | 保持 0 | 当前脚本不提供，保持 0 | m/s |
| `angular.x`、`angular.y` | 保持 0 | 保持 0 | 当前脚本不提供，保持 0 | rad/s |

在当前初始水平姿态下，`linear.x > 0` 为向前，`linear.x < 0` 为向后；`linear.z > 0` 为上升，负值为下降。Gazebo 的 Z 轴向上，`angular.z > 0` 为俯视逆时针转向，负值为顺时针转向。不要直接把 UE 坐标系的符号套用到 ROS 命令中。

完整消息示例（前进 0.2 m/s，同时以 0.1 rad/s 转向）：

```yaml
linear:
  x: 0.2
  y: 0.0
  z: 0.0
angular:
  x: 0.0
  y: 0.0
  z: 0.1
```

停止命令为六个分量全部为 0。`Twist` 本身没有“持续几秒”或“目标坐标”字段，持续时间由发令程序管理。

## 4. Windows PowerShell 控制示例

在下面的工程目录打开 PowerShell，先确保 `Start-Gazebo.ps1` 已启动并显示 `POSE_SERVER_READY`。

```powershell
cd 'C:\Users\Administrator\Documents\Codex\2026-10-21\20-50\outputs\GazeboUEBridge'

# 仅在当前窗口的执行策略阻止脚本时使用
Set-ExecutionPolicy -Scope Process Bypass

# 1 号无人车前进
.\Drive-Robot.ps1 -Robot 1 -Linear 0.2 -Seconds 5

# 21 号坦克原地转向（必须显式指定 Linear 0）
.\Drive-Robot.ps1 -Robot 21 -Linear 0 -Angular 0.2 -Seconds 5

# 31 号常规固定翼前进并上升
.\Drive-Robot.ps1 -Robot 31 -Linear 1 -Vertical 0.3 -Seconds 5

# 41 号飞翼前进并转向
.\Drive-Robot.ps1 -Robot 41 -Linear 1 -Angular 0.1 -Seconds 5

# 停止 41 号机器人
.\Drive-Robot.ps1 -Robot 41 -Linear 0 -Angular 0 -Vertical 0 -Seconds 0
```

| PowerShell 参数 | 对应含义 | 默认值 |
|---|---|---:|
| `-Robot` | 机器人编号，1–50 | 1 |
| `-Linear` | `linear.x` | 0.2 |
| `-Angular` | `angular.z` | 0 |
| `-Vertical` | `linear.z`，只允许 31–50 | 0 |
| `-Seconds` | 持续发令的墙钟时长，0–120 秒 | 5 |

脚本在 WSL 中等待 ROS bridge 订阅者，约每 0.05 秒发送一次命令，正常结束时重复发送全零速度。这里约 20 Hz 是命令发送频率，不代表仿真、图像或位姿同步达到 20 Hz。旧 `Drive-Rover.ps1` 仍可用于前进和转向，新接口统一使用 `Drive-Robot.ps1`。

速度按仿真时间生效，`Seconds` 按实际墙钟时间计算。例如 RTF 低于 1 时，不能用“速度 × 实际发令秒数”推算实际位移。

## 5. 在 WSL 中直接发布 ROS 2 命令

打开 Ubuntu-22.04 终端，设置与本工程一致的环境：

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=46
export ROS_LOCALHOST_ONLY=1
```

以下每条移动命令都会持续发布，按 Ctrl+C 停止发布后，**还要发送对应的全零速度命令**。

```bash
# 无人车：1 号前进
ros2 topic pub -r 20 /rover_01/cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.2}}'
# Ctrl+C 后停止该车
ros2 topic pub --once /rover_01/cmd_vel geometry_msgs/msg/Twist '{}'

# 坦克：21 号原地转向
ros2 topic pub -r 20 /rover_21/cmd_vel geometry_msgs/msg/Twist '{angular: {z: 0.2}}'
# Ctrl+C 后停止
ros2 topic pub --once /rover_21/cmd_vel geometry_msgs/msg/Twist '{}'

# 常规固定翼：31 号前进并上升
ros2 topic pub -r 20 /rover_31/cmd_vel geometry_msgs/msg/Twist '{linear: {x: 1.0, z: 0.3}}'
# Ctrl+C 后停止
ros2 topic pub --once /rover_31/cmd_vel geometry_msgs/msg/Twist '{}'

# 飞翼：41 号前进并转向
ros2 topic pub -r 20 /rover_41/cmd_vel geometry_msgs/msg/Twist '{linear: {x: 1.0}, angular: {z: 0.1}}'
# Ctrl+C 后停止
ros2 topic pub --once /rover_41/cmd_vel geometry_msgs/msg/Twist '{}'
```

这些命令可由 Python `rclpy` 或 C++ `rclcpp` 发布器替代。当前 `drive.py` 创建的发布器队列深度为 10。已有 PowerShell 接口是通过 WSL 执行 ROS 2，因此不要求 Windows 安装 ROS 2。当前 `ROS_LOCALHOST_ONLY=1` 配置面向本机 WSL 使用，其他电脑不能直接按上述配置接入。

## 6. 位姿反馈与话题检查

移动命令与位姿反馈是两个不同方向：

| 用途 | ROS 2 话题 | ROS 2 消息类型 | 方向 |
|---|---|---|---|
| 控制机器人移动 | `/rover_XX/cmd_vel` | `geometry_msgs/msg/Twist` | 控制程序 → Gazebo |
| 获取机器人位姿 | `/model/rover_XX/pose` | `tf2_msgs/msg/TFMessage` | Gazebo → ROS 2 → UE |

例如检查 31 号飞机：

```bash
ros2 topic list
ros2 topic info /rover_31/cmd_vel -v
ros2 topic echo /rover_31/cmd_vel
ros2 topic echo /model/rover_31/pose
```

`cmd_vel` 无发布器发令时没有消息是正常情况。命令话题有 bridge 订阅者，不等于已经验证 Gazebo 内控制插件正常执行；还应观察位姿是否变化。当前位姿消息的 frame 元数据带有私有延迟测量信息，由 `pose_server.py` 解析，不应直接当作标准 `/tf` 树使用。

每台机器人的图像目前由 UE 相机输出到面板和 PNG 文件，**尚未发布为 ROS 2 Image 话题**。

## 7. 当前功能边界与操作注意

- 无人车采用差速驱动；坦克虽然换成履带外观，底层仍是差速轮驱动代理，没有真实履带接地与滑移动力学。
- 两类固定翼采用关闭重力的刚体和 Gazebo `VelocityControl`。升降、转向是简化运动控制，不是油门或舵面指令；未接入气动模型、失速、飞控或自动起降。
- 当前没有“到达目标点”“执行航线”“自动避障”等任务话题或 Action。增加这些能力需要额外导航/飞控模块，将目标转成底层指令。
- 同一机器人只安排一个持续发令源。另一个程序持续发令时，单次停止命令可能立即被覆盖。
- 当前未增加独立的命令超时自动停车机制，不能把发布器退出或通信中断当作停止命令。地面机器人收到零速度后也可能有短暂减速过程。
- 暂停 UE5 只暂停 UE 播放，不暂停 Gazebo。暂停期间不要根据冻结的 UE 画面判断机器人已经停止。
