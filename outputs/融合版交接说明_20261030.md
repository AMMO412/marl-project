# 融合版交接说明（给另一方）

日期：2026-10-30

用途：交接当前实现、接口格式、验证结果与未完成项

## 0 一句话结论

以你的 `planning_middle_demo` 为基座，新建 `interop/` 作为 **1028 4.1/4.2 统一接口 + 中性任务规划层**，吸收 M2 的消息契约、任务分解、能力闸门、协同组匈牙利、三目标、风险 A*、SDF 解析和报表结构；基座的协调器、反馈、行为层、工作台保持运行职责。M2 源码未修改，只作为只读对比后端。

**范围边界**：只做四类中性任务（T-RCN / T-SEC / T-PTL / T-HLD）；不含 T-ASL、攻击阵位、`fires`、毁伤/压制/夺占效果判定。`asl_city` 历史场景仍可查看/运行，但走基座原规划器与行为链，不经过 interop。

## 2 结构

```text
4.1 任务消息（schema 0.3）+ 编成表
        ↓  interop.message           严格解析/校验
Scenario（平台、任务、约束、meta）
        ↓  interop.templates         四类任务分解
        ↓  interop.gate              能力/窗口/续航/禁入区闸门
        ↓  interop.assignment        协同组匈牙利
        ↓  interop.routing           风险感知 A*
        ↓  interop.cost              时效/风险/能耗
        ↓  interop.scheduler         排程 + 校验
4.2 计划层 assignments + 执行层 commands
        ↓  interop.output            plan.json/CSV/report/manifest/ros2_commands.txt
```

运行：

```text
interop.runtime.InteropPlanner   ← 快照平台位姿/存活/在途占用/剩余工作量
        ↓  槽位分配折回 job 级 Assignment
CoordinatorV2                     ↓ 下发/反馈/取消/重试
MockFleet / 工作台回放
```

## 4 同轮修正的 M2 问题

1. **拆分不读 `max_units`**：M2 的区域/路线拆分会超过兵力上限；融合版取上限（对比中 T1 上限 3 台、M2 用了 4 台）。
2. **`simultaneous_arrival` 只是标签**：M2 不保证同时开始；融合版统一组内开始时刻。
3. **协同组平台会被别的任务抢走**：融合版在组内全部槽位处理完前预留平台，失败也会释放。
4. **父任务目标禁入区未检查**：融合版整组拒绝。

## 6 Gazebo / ROS 2 接口：做到哪一步

### 6.1 已完成的格式层

| 项 | 状态 | 证据 |
|---|---|---|
| 移动话题 `/container_00/robot_XXX` | ✅ 完成 | `fleet.topic_of()`；plan/CSV/report/delivery 都走它 |
| 三位编号 | ✅ 完成 | `robot_001`…`robot_050` |
| `geometry_msgs/msg/Twist` | ✅ 完成 | `ros2_commands.txt` 每条带该类型 |
| `ros2 topic pub -r 20 <topic> "<Twist>"` | ✅ 完成 | `interop/output.py:ros2_pub_line()` |
| 六分量 Twist | ✅ 完成 | `commands[].twist`；STOP 六分量全零 |
| 位姿话题 `/model/robot_XXX/pose` | ✅ 完成 | `delivery_block.pose_topic` |
| 计划契约校验 | ✅ 完成 | `interop.cli validate` 检查话题与 robot_id 一致、STOP 全零 |
| 20 Hz 说明 | ✅ 完成 | 命令带 `-r 20`；实际持续时长由 `at_s/duration_s` 管理 |

实际输出（`outputs/interop_demo/doc_check/ros2_commands.txt`）：

```text
# CMD-00027  at=0.000 s  duration=5.307 s  phase=TRANSIT
ros2 topic pub -r 20 /container_00/robot_041 geometry_msgs/msg/Twist "{linear: {x: 25.000, y: 0.000, z: 0.000}, angular: {x: 0.000, y: 0.000, z: 0.500}}"
```

和你给的示例的区别：

- 你示例里的 `Z` 是大写笔误，ROS 2 的字段必须小写 `z`；
- 你示例里话题末尾有 `/`，ROS 2 话题名不以 `/` 结尾，按无后缀输出；
- 命令是单行，避免了换行/续行符在不同 shell 下的差异。

### 6.2 还没做的

| 项 | 状态 | 说明 |
|---|---|---|
| ROS 2 发布器节点 | ❌ 未做 | 没有 `rclpy` 节点；`ros2_commands.txt` 只是文本命令 |
| 20 Hz 定时发布 | ❌ 未做 | 命令文本标了 `-r 20` 和时长，但没有自动按时间轴播放 |
| Gazebo/UE 联调 | ❌ 未做 | 没有向真实 Gazebo 发布过，也没有确认桥接订阅 |
| 仓库里的桥接脚本 | ⚠️ 不一致 | `gazebo/GazeboUE-single-container-v1/linux/run_gazebo.sh` 仍桥 `/robot_XXX/cmd_vel`，不是 `/container_00/robot_XXX` |

**这一点很关键**：规划侧输出的是 `/container_00/robot_XXX`，但如果你实际运行的是仓库里那份 `run_gazebo.sh`，桥接订阅的是 `/robot_XXX/cmd_vel`，消息不会到达 Gazebo。两种处理：

1. 改桥接：把
   `args+=("/robot_${i}/cmd_vel@geometry_msgs/msg/Twist]ignition.msgs.Twist")`
   改成
   `args+=("/container_00/robot_${i}@geometry_msgs/msg/Twist]ignition.msgs.Twist")`；
2. 不改桥接：给规划侧设环境变量
   `FLEET_CMD_TOPIC_TEMPLATE=/robot_{robot_no:03d}/cmd_vel`，输出就会退回桥接当前订阅的名字。

如果实际话题是 `/container_00/robot_041/cmd_vel`，设 `FLEET_CMD_SUFFIX=/cmd_vel`。这两种都不需要改规划代码。

### 6.3 建议的联调顺序

1. 先只看文本：`python -m interop.cli plan ...`，打开 `ros2_commands.txt` 核对话题/字段；
2. 在工作台跑一遍 `interop_neutral`（逐步运动），确认计划包 5 个文件；
3. 在 Gazebo 侧先 `ros2 topic list | grep robot_041` 确认实际话题名；
4. 用 `ros2 topic pub --once <实际话题> ... '{}'` 发一次全零，确认桥接和 Gazebo 都收到；
5. 再按 `at_s/duration_s` 用脚本发布；不要假设 `-r 20` 会自动停。

## 8 已知边界

1. 不覆盖 T-ASL、攻击阵位、`fires`、毁伤/压制/夺占效果；`asl_city` 仍走基座原链。
2. 不发布 ROS、不启动 Gazebo；`ros2_commands.txt` 只是命令文本。
3. `motion=real` 是基座 `MockFleet` 的逐步运动替身（`GoalController` 先转后走），**不是**按 interop A* 航点逐点跟随；工作台轨迹是反馈位姿重建，和 `plan.json` 的 `path` 可能不同。
4. `to-v2` 只做有损性检查，缺能力就拒绝并不写文件；运行视图走 `_meta.interop`，不冒充等价旧场景。
5. 能耗/风险系数是演示值；跨后端不能比绝对值。
6. 工作台里 `asl_city` 是历史入口，不代表融合层支持突击。

## 9 给接手方的建议

1. 先读 `docs/融合版代码讲解_20261030.md` 的 3、7、8 节，跑通 `plan` 与 `validate`；
2. 如果要在 Gazebo 里验证，先解决第 6.2 节的话题映射（bridge 或环境变量），不要先改规划代码；
3. 需要新增任务类型时，从 `interop/templates.py` + `interop/message.py` 的 `TASK_TYPES` 入手，并补测试；
4. 任何真实运动/发布能力都应作为独立适配器加入，不要把 `MockFleet` 的反馈当作 Gazebo 实测；
5. 历史 `asl_city` 的规划/行为/效果链不在本次融合范围，改动前先确认责任边界。
