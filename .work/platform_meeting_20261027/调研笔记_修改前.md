## 与当前工程衔接时最容易混淆的点

1. **履带外观不等于履带动力学。** Gazebo 提供 `TrackedVehicle` 与 `TrackController`，并有 [tracked_vehicle_simple.sdf 示例](https://github.com/gazebosim/gz-sim/blob/gz-sim8/examples/worlds/tracked_vehicle_simple.sdf)。它提供接地履带运动近似，不能据此宣称软土沉陷、真实悬挂或真实坦克性能已验证。[插件说明](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1TrackedVehicle.html)
2. **Twist 是消息类型，不是平台能力标准。** 当前文件的飞机前进、爬升、偏航来自速度代理。正常固定翼飞行的零速度命令不能沿用为“空中停车”；修改质量也不会让直接速度控制自动变成受推力约束的飞行。[VelocityControl](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1VelocityControl.html) / [LiftDrag](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1LiftDrag.html)
3. **公开航程不能直接填成续航时间，标称续航不能直接充当所有工况的倒计时。** 行驶里程、通信控制距离、滞空时间是不同量；最大载荷与最长续航未必能同时实现。坡度百分比也不等于角度。
4. **同名 Zephyr 不证明当前模型与上游完全相同。** 上游气动配置 `forward` 是 `0 -1 0`，而当前文件的控制语义是 `linear.x` 向前。须检查 mesh 朝向、link 坐标与模型变换，不能直接拼接参数。
5. **先确认实际 Gazebo 版本。** 文件写 ROS 2 Humble 与 `ignition.msgs.Twist`，不足以确定具体 Gazebo 发行版。Classic 与新 Gazebo 的模型/插件不能默认互换；PX4、ArduPilot、Clearpath 的候选路线也有各自版本要求。[PX4 版本提醒](https://docs.px4.io/main/en/sim_gazebo_gz/vehicles)
6. **按仿真时间核对位移。** 用户文件说明发令持续时长按墙钟计算，速度按仿真时间生效。低实时因子下，不能直接用速度乘墙钟秒数验证模型。

### 指标的实现位置

- **消息层**：Twist 只有线速度与角速度两个三维向量，没有 Header、目标点、持续时间、质量、载荷或续航。相同 cmd_vel 类型不表示四类平台动力学相同。[消息定义](https://github.com/ros2/common_interfaces/blob/humble/geometry_msgs/msg/Twist.msg)
- **物理层**：质量、重心、惯量分别在 link/inertial 的 mass、pose、inertia；外观和碰撞体要分别配置。实际载荷应改变质量分布，额定载荷上限则需要外部逻辑校验；只填容量不会自动加载物理质量。[SDF 惯性定义](https://github.com/gazebosim/sdformat/blob/sdf12/sdf/1.9/inertial.sdf)
- **差速运动**：DiffDrive 有 max_linear_velocity、max_angular_velocity 及分开的加速度限制。源码写入 JointVelocityCmd；指令加速度受限不等于已模拟真实电机功率、传动与满载响应。[参数接口](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1DiffDrive.html)
- **履带运动**：TrackedVehicle 与 TrackController 通过接触面运动近似履带推进；官方说明仅支持速度控制，无 effort 控制，不模拟履齿效应。爬坡和越障应作为指定工况下的测试结果，不能假设存在通用 max_slope 字段。[官方边界](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1TrackController.html)
- **飞机代理**：所查 gz-sim8 VelocityControl 直接更新模型速度，没有 DiffDrive 同名限速字段的读取逻辑，且保存最新命令持续使用。限幅、加速度、指令超时与能源状态联动需另行实现和验证。[源码](https://github.com/gazebosim/gz-sim/blob/gz-sim8/src/systems/velocity_control/VelocityControl.cc)
- **续航**：LinearBatteryPlugin 的 capacity 单位 Ah、power_load 单位 W；可通过消费者汇入附加功耗。所查源码支持 start_draining，而 API 页出现 start_drainign 拼写。源码从关节命令检测运动并启动耗电，模型级速度代理可能绕过这条触发路径；耗尽后关节停机也不能直接推断会停止 VelocityControl。[源码](https://github.com/gazebosim/gz-sim/blob/gz-sim8/src/systems/battery_plugin/LinearBatteryPlugin.cc) / [电池教程与历史问题](https://gazebosim.org/api/sim/8/battery.html)

2. **CitySim 的可视地形不等于碰撞地形。** 本次固定版本 `models/city_terrain/model.sdf` 的 visual 使用高度图，collision 实际为 500×500 m 平面，碰撞高度图被注释；不能用画面判断爬坡能力。
3. 原生 gz-sim8 差速车示例已读出质量 6.14395 kg、命令限速 ±0.5 m/s 和 ±1 rad/s；履带示例质量 28.26 kg、单侧 TrackController ±1 m/s。两者已提取独立 SDF，**尚未运行**；履带速度不能直接冒充实测车速或真实重型平台性能。
4. 飞机继续采用此前公开参考：rc_cessna 显式 link 总质量约 1.67000006 kg，Zephyr 基础及 include 展开为 1.9 kg。传感器频率、碰撞盒与气动参数已保留；没有从模型中推造最高速度或续航。
5. TurtleBot3 Burger 提供另一个带激光/IMU 的模型来源。厂家表的速度 0.22 m/s、尺寸 138×178×192 mm、期望运行 2 h 30 min 属**产品页参考**；下载 SDF 未体现这些续航与车体限速，且采用 Classic 插件。不能与新 Gazebo 示例混称即插即用同版环境。

### 复用方法与未完成项

`inspect_assets.py` 使用 Python 标准库，实际在 Windows Python 3.12.15 执行；本次交叉核对了文件哈希、坐标、度转弧度、道路端点、include 质量及碰撞/显示区别。电池示例注释含不合法 XML 双连字符，解析器只在内存忽略注释，原文件保持不变。

建议下一步先用同版官方差速世界核验单车反馈，再补齐仓库资源和碰撞地图，定义普通巡检/取送工单，跑规则分配→导航→反馈→完成/重试闭环，最后再比较 MARL。此顺序为建议，未实施；当前沙盒结果不能代替 Gazebo 联调证据。
