## 新旧数字怎样分别验收

| 数字 | 所属材料及对象 | 尚需确定 |
| --- | --- | --- |
| ≥20 独立实例，每实例 ≥50 机器人 | 新平台规模 | 机器配置、模型复杂度、传感器组合、训练是否并发满载 |
| 复杂场景 RTF ≥2 | 新仿真性能 | 场景版本、负载、测量时段及是否含采集与 UE5 |
| UE5 P99 ≤100ms | 新实施方案及外协同步目标 | 测点、时钟对齐、样本频率、丢帧、展示缓冲 |
| kill 后 30s 内重启 | 新平台恢复 | 进程重启、服务就绪和训练恢复分别如何证明 |
| D20/D30/D40/D50 | 新方案相对里程碑 | D1 起算日期、日历日/工作日、人员与依赖 |
| ≥15 台、总耗时 ≤800ms | 旧任务规划要求 | 计时起止、负载和输出确认边界 |
| 接收 ≤50ms、同步误差 ≤50ms | 旧接入与时间对齐要求 | 与新 UE5 显示延迟是不同测量对象 |
| 20 回合内消解率 ≥95% | 旧指标 | 回合、分母、复发、无冲突及观察窗口均须定义 |

新方案写出的 200ms / 1.5x / Dense-only 均是拟议降级项，没有本次已取得批准的证据。不能默认按降级值验收。≥2x 也不能由 `dt=0.005` 或 headless 配置直接推出。

“奖励有上升趋势”“两种奖励均可收敛”“50 episode 验证”缺少种子、评估策略、稳定区间和统计定义；适合探索性 PoC，不足以证明正式效果。CartPole-v1 的 195 分写法应按具体环境版本与独立评估协议重写。
