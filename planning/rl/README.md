# rl —— 强化学习部分

## 做了什么

`learn_weights.py`：用**进化策略（CEM）学习代价函数的权重**。

设计上遵循方案的分层：**规则层管可行性，学习层管偏好**。
学习只改"怎么在可行集里挑"，不动能力约束——所以学到的再差也不会越界。

被学的对象是 8 维权向量（见 `planner._features()`）：

| 维 | 含义 | 作用在哪一步 |
| --- | --- | --- |
| 1 | 移动时间 | 第 2 步 打分 → 第 3 步 分配 |
| 2 | 作业时间 | 同上 |
| 3 | 能耗 | 同上 |
| 4 | 拥挤度（暴露风险代理） | 同上 |
| 5 | 载荷余量 | 同上 |
| 6 | 续航余量 | 同上 |
| 7 | 窗口余量（新增） | 同上 |
| **8** | **`URGENCY_WEIGHT` 排程紧迫度权重（新增）** | **第 5 步 排程（谁先干）** |

第 8 维是后来才加的，原因是一个架构事实：

> **只学前 7 维，治不了「短视」。**
> 短视发生在**排程**阶段（同一台平台上谁先干），而排程是按"谁先开工"排序的，
> **根本不看代价函数**。所以代价权重怎么学，都影响不了谁先干。

奖励函数（**我方暂定**，见 `spec/SPEC.md`）：

```
奖励 = 100×完成数 − 0.3×能耗 − 5×冲突数 − 50×方案级越界 + 50×消解率
```

## 结果

跑法：

```bash
python rl/learn_weights.py --tasks 8  --gens 6 --samples 12 --seeds 0 1
python rl/learn_weights.py --tasks 16 --gens 6 --samples 12 --seeds 0 1 --steps 90
```

### 作业数 8：提升 0%

| 权重来源 | 奖励 |
| --- | --- |
| makespan 手工 | 477.4 |
| **energy 手工** | **573.3** |
| dispersion 手工 | 522.7 |
| 学习所得 | 573.3（**+0.0%**） |

学习过程确实收敛（精英均值 383 → 573），但**没超过最好的手工权重**。

### 作业数 16：提升 13.6%

| 权重来源 | 奖励 |
| --- | --- |
| makespan 手工 | 610.0 |
| energy 手工 | 645.5 |
| dispersion 手工 | 414.2 |
| **学习所得** | **747.0（+13.6%）** |

学到的权重：`0.09 0.01 0.53 0.00 0.00 0.08` —— 主要压能耗，略压移动时间。

## 这个对比说明什么

> **强化学习有没有用，取决于"分配决策是不是瓶颈"。**

- 作业少、资源相对宽裕时，结果由**约束**决定（能不能派得出去），不由分配策略决定 → 学习没有空间
- 作业多、资源紧张时，**怎么分配**才有讲究 → 学习提升 13.6%

顺带纠正一个直觉：放宽续航 3 倍，结果**一个数字都没变**。
这说明瓶颈不是续航，而是时间窗和分配。别凭感觉定位瓶颈。

## 一次"失败"的实验，但结论有价值

假设：时间窗收紧后紧迫度会变重要，学习应该学到非零的 `URGENCY_WEIGHT`。
实测（紧窗口 0.4×）：**学到的仍是 0.00，相对手工提升 −36.2%。**

先别急着说学习失败——去验证 UW 到底有没有用：

| 场景 | UW=0 | UW=0.1 | UW=0.3 | UW=0.8 |
| --- | --- | --- | --- | --- |
| 15 平台 / 8 作业 | 405.6 | **405.6** | 366.0 | — |
| 5 平台 / 8 作业 | 67.3 | **67.3** | 65.0 | — |
| 3 平台 / 8 作业 | 124.1 | **124.1** | 73.4 | — |
| 紧窗口(0.4×) | 92.3 | **92.3** | 57.8 | −8.0 |

**随机场景里紧迫度权重完全不影响结果（0 与 0.1 一字不差），调大反而有害。**

→ **学习把 UW 设成 0 是对的**，错的是我"窗口紧就该看紧迫度"的假设。
资源宽松时谁先干都来得及，紧迫度自然无意义。

`tests/test_myopia.py` 那个场景 UW=0.1 确实能治好短视（B 5→15 ✓、A 15→27 ✓），
但那是**一台平台两个活**的极端构造，不代表一般情况。

> **真正的解法不是调紧迫度，而是让决策看得见全局状态。**
> 这正是真 MARL 与"学一组固定权重"的根本区别：
> 固定权重在任何场景下都一个样；策略可以**看情况**决定急的先干还是近的先干。

## 局限（必须说清）

1. **只学 8 维权重的表达力有限。** 真正的 MARL 是学"每个平台选哪个作业"的策略，表达能力强得多，也是唯一能真正治短视的路子。这是 WP4 要做的。
2. **奖励函数是我方暂定的**，没经甲方确认。所以"学到了更好的决策"的完整说法是：
   「在这个奖励定义下，学习找到了比手工权重更好的一组偏好」。
3. 样本量小（2 个 seed × 6 代），结论是初步的，不是算法排名。
4. 进化策略是无梯度方法，不等于 PPO/QMIX 那一类策略梯度方法。
