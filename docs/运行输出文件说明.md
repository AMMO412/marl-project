# 每轮运行输出文件说明

核对日期：2026-11-16。文件以 `workbench_server.py`、`chain_trace.py` 和运动导出实现为准，历史/失败/手动结束运行可能只有部分文件；不再用固定“25 个文件”描述所有版本。

## 保存位置

当前本机工作台默认保存到 **`desktop_app/dist/data/runs/<运行编号>/`**。未建立该目录时回退 `planning_middle_demo/outputs/`；`MARL_WORKBENCH_OUTPUTS` 环境变量优先，可从 `GET /api/catalog` 的 `outputs_root` 核对。根 `outputs/` 是精选工程证据，不是当前运行目录。

## 常用文件

| 文件 | 含义 |
| --- | --- |
| `report.json` / `summary.txt` | 任务、平台、统计与结束原因；手动结束会保留 `manual_stopped` / `termination_reason`，未完成不算成功 |
| `agent_tasks.md` / `.csv` / `.json` | 单平台任务、子任务、时序、窗口和协同约束的不同阅读格式 |
| `request.json` / `desktop_input.json` | 本轮请求与冻结的编辑输入；复现及复制草稿使用 |
| `input_message.json` / `input_formation.json` | 原始 4.1 消息和编成，保留业务输入依据 |
| `scenario.json` | 运行器派生视图，不替代原始输入 |
| `trace.jsonl` | 实际审计事件、反馈及行为采样，供回放与执行核对 |
| `plan.json` / `assignments.csv` / `commands.csv` | 静态 4.2 计划参考；不等于已经执行 |
| `planning_history.json` / `execution_plan.json` | 动态计划版本、任务尝试、下发指令和执行段关联 |
| `motion_commands.json` / `.csv` | 实际运动采样导出的六分量机体坐标系速度序列，包含关联字段及连续性检查 |
| `ros2_plan_node.py` | 独立节点；优先完整运动文件，没有时兼容静态计划，可 `--dry-run` 离线检查 |
| `chain_viewer.html` / `chain_summary.json` / `chain_verification.json` | 可视追溯、汇总和完整性检查 |
| `chain_raw.json` / `archive/` | 实际收发消息、任务/子任务/指令/反馈关联与动态事件 |
| `initial_config.json` / `final_config.json` / `run_meta.json` | 运行前后配置及归档元数据 |
| `manifest.json` | 文件清单、配置、校验和与证据元信息 |
| `worker.log` | 后台进程输出和异常线索，正常时可能为空 |

续算使用暂存目录验证，发布后保留旧版本于 `.run_revisions/`；工作台删除记录使用 `.deleted/`，不得作为普通缓存清空。`.live_*` 文件是运行中的快照与控制通道，运行时不手工清理。

## 阅读与判断

先看报告确认状态和未完成原因，再看单平台明细及追溯。`timing_resolution` 的新消解率统计配置变更后的真实子任务切换，`scheduler_timing_resolution` 保存原时序诊断，两者不能混作同一指标。

同一数据的 JSON、CSV、Markdown 用途不同，不能凭内容相似删除；轨迹、输入和归档也不能根据文件大小或任务失败判定无用。旧 `report.html`、`trajectory.html`、`report.md`、`ros2_commands.txt` 可能来自历史版本或 CLI，不是每轮必备文件。

本地轨迹、按时序速度发布和真实定位闭环是不同验证层级。追溯校验通过只证明关联和哈希一致，不保证任务成功或外部平台联调完成。
