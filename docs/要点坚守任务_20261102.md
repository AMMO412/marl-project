# 要点坚守（T-HLD）实现说明 · 2026-11-02

> 依据：《无人集群编队五类任务定义》2.5 T-HLD（要点坚守）与 1.4/1.5 的判定、结算口径；
> 实现模板见 `docs/任务实现模板_区域封控复盘与要点坚守任务书_20261102.md` §9。
> 主体是融合版：`interop` 负责 4.1 输入解析与"谁守哪个阵位、谁当预备队"的分解，
> 基座 `CoordinatorV2` / `MockFleet` / `behaviors.KeepBehavior` 负责下发、逐步运动、
> 占位/观察/轮换/增援/撤离；工作台在"演示总览"里以**页签**给出坚守画面。
>
> **结论边界**：这是**本地替身 + 行为状态机 + 4.1 输入回放**，不是真实平台 /
> ROS / Gazebo 联调；效果类条目全部来自 `assessment.Adjudicator` 的桩判定
> （`verified=false`），只作过程证据，不作战果。

## 1.1 场景链路（集结 → 规划 → 占位 → 接替/增援 → 撤离）

样例从**集结区**出发，不是一开局就站在阵位上：

| 时刻 | 发生什么 | 数据来源 |
| --- | --- | --- |
| T+0 | 4 台平台（2 轮式 + 2 履带）在集结区（`assembly_point`，约 100–120 m 外） | 编成表 `formation.units[].position` |
| T+0–17 | 规划器给出"集结地 → 阵位/预备队待机点"的路径，平台按 A* 航迹机动 | `plan.json assignments[].path` + 反馈轨迹 |
| T+17 | 3 个阵位到齐（≥ `min_on_post`=2）→ `control_established`，坚守时段开始计时 | 行为层事件 |
| T+55 / 95 / 135 | 敌方进攻输入事件（N 方向试探 → N 方向突击 ratio 1.6 → E 方向试探） | `enemy_events` |
| T+67–74 | 第 1 次接替：预备队前出 P1，**到位后**原占位者才转预备队 | `handover_start` / `handover_complete` |
| T+95–104 | 按敌我比触发的增援：预备队前出 P1，9 s 到位（时限 60 s） | `reinforce_triggered` / `reinforce_arrived` |
| T+117–126 | 第 2 次接替（P2） | 同上 |
| T+167–180 | 坚守满 `hold_duration_s`=150 s → 开始撤离 → 到达撤离点 | `withdraw_started` / `withdrawn` |
| T+180 | `hold_result` 结算：判定项、指标、阵位在位区间、时间线、桩判定清单 | 行为层事件 |

## 2 链路与职责

| 层 | 文件 | 负责 | 不负责 |
| --- | --- | --- | --- |
| 4.1 输入 | `interop/message.py` | 任务/编成表解析校验 | 战术意图 |
| 分解 | `interop/templates.py::_decompose_hld` | 阵位/预备队/支援/中继到平台、兵力裁剪 | 选点后绕障细节 |
| 几何 | `containment_geom.py`（要点几何一节） | 方位角/威胁扇区/阵位点/观察采样环 | 遮挡、识别概率 |
| 规划 | `interop/scheduler.py` | 能力闸门、协同分配、风险 A*、排程 | 阵位使用策略、轮换时机 |
| 运行视图 | `interop/runtime.py::_hld_behavior_params` | 白名单透传 4.1 → `_behavior`（含 `stations`） | 改写任务语义 |
| 执行 | `behaviors.py::KeepBehavior` | 占位、观察、接替/轮换、增援、撤离、过程记账 | 弹道、命中、毁伤/杀伤模型 |
| 判定 | 同上 `_verdict` + `assessment.StubAdjudicator` | 逐项判据 + 全过程时间线 + 桩判定 | 预测"能不能守住" |
| 回放 | `trajectory_v2.py::_hold_replay` + `workbench/hold.js` | 画要点/阵位/威胁扇区/在位甘特 | 前端重算几何与指标 |

关键约束：**规划层与执行层共用 `containment_geom` 的要点几何**。计划里
"U1 守 P1（朝向 0°）"与执行层 `post:P1` 用的是同一个点、同一套角度，否则
"守错阵位/朝向反了"在数据上看不出来。角色随指令下发（`task_block.roles`），
执行层优先采用；只有在角色缺失或指向不存在阵位时才按几何补位。

## 3 4.1 任务参数（T-HLD）

`target` 给 `key_point`（或 `defense_area`，取形心当要点）；其余在 `params`：

| 字段 | 含义 | 样例 |
| --- | --- | --- |
| `hold_duration_s` | 坚守时段（从控制建立起算） | `150` |
| `threat_directions` | 威胁方向：`[{id, bearing_deg, width_deg}]`（0°=北，顺时针） | `N/0°/70°`、`E/90°/60°` |
| `positions` | 预设阵位：`[{id, point, facing_deg, min_units}]` | `P1/P2/P3` |
| `roles` | 兵力组成：`{post, reserve, support, relay}` 台数 | `3/1/0/0` |
| `min_on_post` | 同时在位下限（数量口径） | `2` |
| `hold_criteria` | 判定口径：`quantity`（在位数量）/ `coverage`（观察覆盖） | `quantity` |
| `sensor_radius_m` | 传感器作用距离（观察覆盖同一口径） | `45` |
| `observation_ring_m` / `observation_samples` | 要点观察采样环半径与采样数 | `24` / `12` |
| `observation_gap_max_s` | 允许观察中断（秒） | `8` |
| `relief` | `{interval_s, handover_tol_m, swap_requires_arrival, relief_cycles}` | 50 s / 3 m / true / 2 |
| `reinforce` | `{trigger, enemy_ratio, arrive_within_s}` | `position_lost` / 1.5 / 60 |
| `withdraw` | `{allowed, route, deadline_s}` | true / 两段路线 / 45 |
| `enemy_events` | 敌方进攻**输入事件**：`[{t_s, kind, direction, ratio}]` | 3 条 |
| `counter_attack` | 阵内反击/火力控制：`{authorized, max_range_m}` | true / 70 |
| `effect` | 抽象效果：`{kinds, adjudicator, required_duration}` | damage/suppress/stub/8 |
| `assembly_point` | 集结区中心（画面标注用；实际出发点取自编成表） | `[-90,-16]` |
| `post_radius_m` | 未给 `positions` 时按威胁方向布点的半径 | `30` |

未给 `positions`/`threat_directions` 的旧输入（只给 `defense_positions` 点列）仍按
原语义分解，槽位数不变，只是补上 `post:Pn` 角色与朝向——历史样例不受影响。

## 4 执行语义（1028 §2.5 时序）

1. **机动进场**：从集结地按 4.2 路径进入阵位/待机点，记录到达时刻。
2. **占位**：阵位到点 → 在位；有效在位数量达到 `min_on_post` →
   `control_established`，坚守时段开始计时。在位判定按阵位半径（`post_tolerance_m`），
   不是"离作业点 ≤ ε"。
3. **观察**：按阵位朝向与传感器半径对**固定采样环**统计覆盖；覆盖为空的连续时长
   超过 `observation_gap_max_s` 记一次 `observation_gap`，恢复记 `observation_restored`。
   一次中断只记一条，不每拍刷屏。
4. **接替/轮换**：到 `relief.interval_s` 由预备队前出；`swap_requires_arrival=true`
   时**接替者到位才撤**，记录 `handover_start` / `handover_complete` 与
   `arrival_before_departure`；未到位不得撤，超时记 `handover_timeout`。
   `swap_requires_arrival=false` 时允许先撤，但照实记成一次控制中断与
   "未到位就撤"的合规缺口。
5. **增援**：敌方进攻输入事件命中阵位且敌我比 ≥ `enemy_ratio`（或阵位失守）→
   `reinforce_triggered`，预备队优先前出；到位记 `reinforce_arrived` 与
   `reinforce_arrival_s`，超 `arrive_within_s` 记 `reinforce_timeout`
   （到达即迟到 → 准时项判失败；一直不到 → 超时事件，结算时该阵位仍空缺）。
6. **阵内反击 / 火力控制（抽象效果，可选）**：仅当 `counter_attack.authorized=true`
   且目标在阵位/射程内 → `counter_attack`，交 `assessment.Adjudicator`（默认桩）出
   `succeeded/failed/pending`，事件与结果都写 `verified=false`；被压制记
   `post_suppressed`，恢复记 `post_restored`。**不生成任何毁伤数值**，
   压制状态只影响观察与在位判定。
7. **撤离/结束**：坚守时段到 → 按 `withdraw.route` 撤离（未授权撤离则原地结束）；
   控制权丧失（有效在位低于下限持续 `control_lost_after_s`）→ 记 `control_lost`，
   有撤离授权则被迫撤离，否则原地结算失败。超 `deadline_s` 记 `withdraw_timeout`。
8. **结算**：`hold_result` 带 `verdict/reason/items/metrics/timeline/positions/
   handovers/reinforcements/effects/scope`。

**控制权判定口径（必须显式写清）**：本层用"有效在位数量 + 阵位状态"代表控制权，
并声明这只是模型近似（1028 §2.5.2 明确覆盖状态不等于现实控制权）。

## 5 指标与判定口径（1028 §2.5 结算）

| 指标 | 计算 | 说明 |
| --- | --- | --- |
| 控制保持率 | 控制在位时间 / 坚守时段 | `quantity` 口径下的主判据，要求 ≥ `min_hold_ratio`（0.9） |
| 控制中断时间 | 有效在位低于 `min_on_post` 的累计秒数 | 要求 ≤ `max_control_interruption_s`（30 s） |
| 最长观察中断 | 阵位覆盖为空的连续时长最大值 | `coverage` 口径下为主判据，阈值 `observation_gap_max_s` |
| 观察平均覆盖 | 采样环被在位平台覆盖比例的时间平均 | 只做参考，不单独判成败 |
| 增援到达时间 | 触发 → 增援到位 | 超 `arrive_within_s` 即判失败项 |
| 敌方突破次数 | 进攻命中时该阵位无人的事件数 | 要求 0 |
| 击退/反击效果 | 桩判定 `succeeded/failed/pending` | **`verified=false`，仅过程证据，不作成功依据** |
| 我方损失 | 失联/损毁平台数 | **代价指标**，不作失败必要条件 |
| 接替合规 | 每次轮换"到位才撤" | 计划轮换不算接替；无预备队跳过也照实记 |

判定：必需项全满足 → `succeeded`；控制权丧失 / 撤离超时 / 必需项失败 → `failed`；
未建立控制，或**本次未出现敌方进攻**（只支持"控制维持"结论，不证明击退/增援能力）
→ `pending`。任何效果类条目都带"桩判定·未验证"标注，**不得把 `pending` 解释成成功**。

## 7 边界与未做

- **效果是桩判定**：反击/压制/击退只由 `StubAdjudicator` 按"在位 + 观察时长"的
  确定性规则给结论，`verified=false`；不建弹道、命中概率、毁伤/杀伤模型，
  也没有武器性能参数。
- **敌方是输入事件**：`enemy_events` 是任务数据（谁从哪个方向、多大规模），
  不是侦察识别结果；本层不建模敌情发现与识别误差。
- **控制权是近似**：用"有效在位数量 + 阵位状态"代替真实控制权，不能写成
  "已确认真实控制"。
- **遮挡与地形未建模**：观察覆盖按距离计算，不做建筑遮挡折算。
- **空中要点未接**：`roles` 目前只到 `post/reserve/support/relay`，没有高度层席位；
  1028 的空中要点（高度层）留待后续。
- **轮换是规则触发**：按 `relief.interval_s` 与预备队可用性走，不是最优排班；
  多阵位同时需要接替时按游标顺序，不排队优化。
- **撤离是单点集合**：`withdraw.route` 只取末点作为集合点，路线本身不逐步跟随
  （画面上按"到点集合"表现），没有沿途警戒与分批撤离。
- **不是物理联调**：本地替身 + 规则状态机，不能作为真实平台/Gazebo/ROS 已验证的证明。
