# 区域封控（T-SEC）实现说明 · 2026-10-31

> 依据：《无人集群编队五类任务定义》2.2 T-SEC（区域封控）与 1.4/1.5 的判定、结算口径。
> 主体是融合版：`interop` 负责 4.1 输入解析与"谁守哪一段"的分解，基座
> `CoordinatorV2` / `MockFleet` / `behaviors.ContainmentBehavior` 负责下发、
> 逐步运动与控制过程；工作台在"演示总览"里以**页签**给出封控画面。

## 1.1 场景链路（集结 → 规划 → 到位 → 封控）

样例从**集结待机区**出发，不是一开局就站在边界上：

| 时刻 | 发生什么 | 数据来源 |
| --- | --- | --- |
| T+0 | 5 台平台在集结待机区待机（`assembly_point`，约 150–220 m 外） | 编成表 `formation.units[].position` |
| T+0–23 | 规划器给出每条"集结地 → 占位点"的路径，平台按 A* 航迹机动 | `plan.json assignments[].path` + 反馈轨迹 |
| T+23 | 占位组/门哨全部到位 → `control_established`，封控时段开始计时 | 行为层事件 |
| T+23–203 | 在岗巡视 + 监视、警告、拦阻、授权放行（见 §4） | 行为层事件与指标 |

封控画面提供两个镜头：**全程 · 集结→占位**（画规划路径与集结点）和
**封控区**；播放到控制建立时自动收到封控区（手动选过镜头后不再自动切）。

**在岗不等于钉在原地**：占位组沿自己负责的边界段来回巡视（限速
`patrol_speed_mps`，默认 2 m/s），门哨在通道口横向游走，机动组在待机点小圈
待机。因此边界监视覆盖率是随时间变化的真实值，图上的监视扇面也会扫过边界，
而不是一个固定站位算出来的常数。

## 2 链路与职责

| 层 | 文件 | 负责 | 不负责 |
| --- | --- | --- | --- |
| 4.1 输入 | `interop/message.py` | 任务/编成表解析校验 | 战术意图 |
| 分解 | `interop/templates.py::_decompose_sec` | 边界段/通道口/机动组/预备队到平台 | 选点后绕障细节 |
| 几何 | `containment_geom.py` | 边界弧长分段、占位点、覆盖统计 | 传感器遮挡、识别概率 |
| 规划 | `interop/scheduler.py` | 能力闸门、协同分配、风险 A*、排程 | 控制等级决策 |
| 运行 | `behaviors.py::ContainmentBehavior` | 监视→警告→拦阻→处置、轮次记录、指标 | 火力、毁伤、效果判定 |
| 判定 | 同上 `_verdict` | 按控制目标逐项判据 + 全过程时间线 | 事后放宽阈值 |
| 回放 | `trajectory_v2.py` + `workbench/containment.js` | 画边界/占位/目标/事件 | 前端重算几何与指标 |

关键约束：**规划层与执行层共用 `containment_geom`**。计划里"U2 守第 1 段"
与执行层 `boundary:1/2` 用的是同一条边界、同一段弧长，否则"守错段"在数据上
看不出来。角色随指令下发（`task_block.roles`），执行层优先采用，缺角色才按
几何补位。

## 3 4.1 任务参数（T-SEC）

`target` 给 `defense_area`（或 `area`/`sector`）多边形；其余在 `params`：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `hold_duration_s` | 封控时段长度（秒），从"控制建立"起算 | `180` |
| `control_objective` | 控制目标：`deny_entry` / `control_passage` / `monitor_channel` / `intercept` | `deny_entry` |
| `control_level` | 控制等级：`monitor` / `warn` / `block`（1028 的监视/警告/拦阻；火力拦阻不在本层） | `block` |
| `engagement_authority` | 交战授权：`none` / `self_defense` / `on_order`；`none` 时只警告不拦阻 | `on_order` |
| `roles` | 兵力组成：`{"boundary":2,"gate":2,"intercept":1,"reserve":0}` | 见样例 |
| `gates` | 通道口：`[{gate_id, point, width, direction}]` | `G-A`/`G-B` |
| `sensor_radius_m` | 传感器作用距离（发现与边界监视同一口径） | `40` |
| `standoff_m` | 占位点相对边界向内收缩的距离 | `14` |
| `intercept_post` | 机动组待机点（缺省多边形重心） | `[95,45]` |
| `intruders` | 目标时间线：`{target_id,start,goal,speed_mps,t_start_s,authorized,compliance}` | 3 条 |
| `assembly_point` | 集结待机区中心（同时用于画面标注；平台实际出发点取自编成表） | `[0,-46]` |
| `max_leak_rate` | 允许漏控率（`deny_entry` 主判据） | `0.0` |

未给 `roles`/`gates` 的旧输入仍按"入口点摆人"的老语义分解，历史样例不受影响。

## 4 执行语义（1028 §2.2.4 时序）

1. **占位建立**：占位组按段号到点，门哨到通道口内侧，机动组在待机点。
   占位/门哨全部到位 → `control_established`，封控时段开始计时。到岗后不是
   站着不动：占位组沿本段边界巡视、门哨在通道口横向游走、机动组小圈待机，
   限速到 `patrol_speed_mps`；前出拦阻时恢复全速。
2. **发现与识别**：目标进入任一在位平台 `sensor_radius_m` 内 → `target_detected`；
   按输入 `authorized` 标记给出"已授权/未授权"（识别过程本层不建模）。
3. **警告**：控制等级 ≥ `warn` 且目标进入警告距离 → `warning_issued`；
   `compliance=true` 的目标警告后退回起点 → `warning_effective`。
4. **拦阻**：警告无效、等级为 `block`、授权不是 `none` → 机动组前出
   （机动组忙时由最近的通道哨位支援）→ 按提前量解算相遇点 → 进入
   `intercept_tol` 判 `intercepted`。
5. **越界**：未授权目标进入多边形 → `breach`（漏控），该目标闭合。
6. **放行**：已授权目标进入区域 → `authorized_pass`，不警告、不拦阻。
7. **结束**：封控时段到期 → `containment_result`，写指标、逐项目标与判定。

控制状态变化（建立/中断/恢复）单独记：占位平台离位超过
`occupancy_tolerance_s` 才记一次 `control_interrupted`，回岗记
`control_restored`，同一次离位不重复刷。

## 5 指标口径（1028 §2.2.8）

| 指标 | 计算 | 说明 |
| --- | --- | --- |
| 未授权进入事件数 | `breach` 计数 | `deny_entry` 主判据，要求 0 |
| 漏控率 | 未授权进入 / 未授权接近 | 无未授权接近时记 0，但判定另按"状态维持"处理 |
| 拦截成功率 | `intercepted` / `intercept_attempts` | 只统计真正下达拦阻的次数 |
| 边界监视覆盖率 | 按秒对边界采样点做"被任一在位平台覆盖"求平均 | 采样间距 `boundary_sample_m`（默认 5 m）；占位平台巡视中，覆盖率随时间起伏 |
| 持续占位率 | 占位/门哨在岗台数比例的时间平均 | 机动组前出不算离岗 |
| 平均响应时间 | 发现 → 指派拦阻的平均时延 | 另记"发现 → 警告"时延 |
| 警告有效率 | 警告后撤离 / 警告数 | — |
| 误拦率 | 授权目标被拦 / 授权通过 | 本版本未建模识别误差，恒 0，**不作能力证明** |

判定项按 `control_objective` 选行，必需项必须全部有证据满足才记"成功"；
本次未出现任何目标接近时记 **结果待确认**（1028：无目标接近只支持状态维持
结论，不证明处置能力）。

## 7 边界与未做

- **不含火力**：控制等级只到"拦阻"，没有武器、毁伤、效果判定与概率预测。
- **识别按输入标记**：`authorized` 是任务数据，不是传感器识别结果；误拦率恒 0。
- **遮挡与地形未建模**：覆盖率按距离计算，不做建筑遮挡折算。
- **巡视是规则扫掠**：幅度受段长与巡逻速度约束（`patrol_speed_mps` /
  `patrol_period_s`），不是覆盖最优化；无证据模型，不能据此宣称最优阵位。
- **无轮换**：`rotation_s` 未实现；平台失联只记中断，不重新分派。
- **空中封控未开**：当前只跑地面平台，`altitude_m` 高度层语义未接入。
- **拦截组规模**：1 个机动组 + 门哨支援；多目标并发时的排队与二次拦截未实现。
- **不是物理联调**：本地替身 + 规则状态机，不能作为真实平台/Gazebo/ROS 已验证的证明。
