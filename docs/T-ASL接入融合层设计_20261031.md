# T-ASL 接入融合层设计（2026-10-31）

> 目的：融合版从四类中性任务扩为五类任务，机动突击（T-ASL）不再被解析层拒绝。
> 本文是实施前的契约与边界说明；实现完成后以代码和测试为准。

## 1 分层

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| `interop` 输入/规划 | 4.1 解析校验、任务分解、能力闸门、协同分配、风险路径、时序排程、4.2 计划产物 | 打击动作、弹道、毁伤/压制/夺占判定 |
| 基座执行 | 指令下发、反馈核对、`behaviors.py` 任务段状态机、`assessment.py` 评估回传 | 规划决策 |
| 工作台 | 计划/执行对照、回放、逐项结算展示 | 改写结论 |

效果判定仍只在执行层：`Adjudicator` 协议不变，默认桩判定继续标注 `verified=false`。
融合层不新增“预测成败”字段。

## 2 4.1 输入契约（T-ASL）

- `task_type: "T-ASL"`，`target` 必须是单点类：`point` / `key_point`（`target_list` 仅允许一个点）。
- `min_units` / `max_units`：本任务总兵力（侦察 + 突击 + 评估）。
- `params`：
  - `effect`：`damage` / `suppress` / `seize`（默认 damage）；
  - `required_level`（毁伤等级）、`required_duration`（连续压制秒）、`required_control_s`（控制秒）；
  - `scout` / `assessor`：`{count, capabilities, unit}`，缺省各 1，能力缺省 `{"RCN": 2}` / `{"RCN": 1}`；
  - `scout_unit` / `assessor_unit`：显式固定席位（可选，需在编成表内）；
  - `payload_required`：突击组载荷下限，默认 4.0；
  - `duration_s`：执行段排程时长，默认 140；
  - `attack_window`、`staging_center`、`objective_radius`、`observe_radius`、`observe_angle`、`assessment_post`、`assessment_delay`、`confirmation_deadline`、`execute_deadline`、`withdraw*`、`roe`、`collateral_limit`、`positive_id_required`、`waves`、`ammo_per_platform`、`target_id`。
- 校验失败一律 `WireError`/`PlanningError`，不静默降级。

## 3 分解与计划

- 模板 `_decompose_asl` 产出三类角色槽位：`scout`（观察位）、`assault`（目标环，数量 = 总兵力 − 侦察 − 评估）、`assessor`（评估位）。
- 突击槽位带 `min_payload`；侦察/评估槽位走 `required_capabilities`；同一父任务已占用的平台不再重复分配。
- 显式 `scout_unit` / `assessor_unit` 时该槽位固定到指定平台；缺省时按编成能力选（RCN 高者侦察、次高者评估），并写回 `_behavior`，保证计划与执行同一批席位。
- 4.2 `assignments` 增加 `role` 与 `min_payload`；`commands` 仍只产 TRANSIT/HOLD/STOP。打击段不在 4.2 表达，由基座行为层按 `task_type/target/start_s/end_s` 接管。
- 报告必须写明："计划只覆盖机动与排程；效果判定来自执行层，桩判定未验证。"

## 4 运行对接

- `to_v2_dict` 对 T-ASL 作业输出 `type="assault"`、`_behavior`、`crew`、`window`，并保留原始 4.1 输入到 `_meta.interop`。
- T-ASL 运行视图带 `_meta.sdf/models/bounds`，与 `asl_city` 使用同一张城市地图；命令行/workbench 自动开行为、避障与逐步运动。
- `InteropPlanner` 对 T-ASL 不改写 `job.work`（突击进度按行为阶段计），只回写 pids/start/end/travel。
- 基座 `planner_v2` 仍保留，作为对照与回退；`--planner auto` 优先 `interop`，T-ASL 不再回退。

## 5 验收

1. 五类任务各至少一条解析/分解单测；T-ASL 拒绝用例改为接受用例。
2. T-ASL 样例（JUNCTION-CROSS-01）跑通：规划产物 + 下发 + 行为 + 评估 + 报告/回放。
3. 现有中性四类回归通过；工作台默认运行不变。
4. 文档与报告口径统一为"五类任务"，删除"不含 T-ASL"的旧表述。

## 6 明确不做

- 真实弹道、命中概率、建筑损毁、目标机动；
- 概率型效果预测或"规划期判定成败"；
- 4.2 新增火力动作类型（本轮不扩执行层指令契约）。
