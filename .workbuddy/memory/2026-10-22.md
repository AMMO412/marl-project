## 第 6 课：RL 接入点与一项重要架构事实

**只学代价权重治不了短视**：短视发生在「排程」阶段（同一平台谁先干），

解法：新增 `planner.URGENCY_WEIGHT`（默认 0.0），直接作用于排程排序键
`start + UW*(window[1]-end)`。UW=0.1 即治好 myopia（B 5-15 ✓、A 15-27 ✓）。
注意排序键**不要归一化**（试过 /50，被稀释到 UW=3 都无效）。

学习维度 6→8：前 7 维代价权重（新增窗口余量），第 8 维 = URGENCY_WEIGHT。

**一次"失败"实验的正确解释**：假设"窗口收紧→紧迫度重要→学到非零 UW"，
实测紧窗口 0.4× 学到的 UW 仍是 0.00、提升 −36.2%。但先验证 UW 是否有用：
15/5/3 平台 × 8 作业 以及紧窗口下，UW=0 与 UW=0.1 奖励**完全相同**，
UW=0.3 起反而变差。→ **学习设 UW=0 是对的，错的是我的假设**（资源宽松时紧迫度无意义）。

myopia（1 平台 2 活）是极端构造，UW 在那里有用不代表一般情况。

## 核实：VD 族"缺员"到底怎么判定（学员质疑，已查源码）

源码 `ray/rllib/env/wrappers/group_agents_wrapper.py:107-120`：
```python
for a in self.groups[group_id]:   # 遍历 group 声明的成员列表
    if a in items:  group_out[a] = items[a]
    else:           raise ValueError("Missing member of group ...")
```
**触发条件是"某一步少返回一个 agent 的数据"，不是"平台不能失联"。**

→ **绕法成立**：保持 agent 数恒定（定长槽位），失联平台**照样返回观测**（标记 alive=False）、
动作被 mask 成"待命"，则不会触发缺员错误。成员损失表现为**状态变化**而非**成员移除**。
这与「规则层管可行性」架构天然契合：失联平台的可行集 = {待命}，由规则层给出。
（注：VD 族模型没有 mask 分支，所以这个 mask 必须在**环境侧**做，不能靠模型。）

**VDN 结果仍有的价值**：它证明在这套环境里完成率可以大幅提升（0.575 vs 随机 0.354），
即**任务本身可学**；MAPPO 只有 0.358 是算法/训练问题，不是任务不可学。
即使最终不用 VDN，这个上界也有参考意义。

**重要概念（数据支撑）**：所有算法 violations 都是 0，包括**没有 mask 分支的 VD 族**
（qmix/vdn 的 jointQ_mlp.py 根本没有 mask 代码）。说明越界为 0 是
**环境侧能力闸门**的功劳，与算法无关。
→ 能力闸门 = **筛掉**非法动作（产出可行集），**不是"选出"**动作；
   在可行集里挑哪个是策略的事。硬保证必须在环境/规则层，不能指望模型里的 mask。
注意 numpy 版本问题导致 `PLOT SKIPPED: numpy.typing has no attribute NDArray`（不影响训练）。
