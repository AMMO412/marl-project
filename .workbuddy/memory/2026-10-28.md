## planning_middle_demo：把到位行为接进工作台主链（--behavior）

用户明确要求：五类任务的到位行为要接进**工作台主演示**（`run_demo_v2.simulate`），与前面的工作连起来，而不是孤立的 `behavior_demo.py`。已实现并验证：

- **接入点**：`run_demo_v2.simulate()` 加 `behavior` 参数（`motion="real"` + `avoid` 时才生效）；`mock_fleet` 在行为模式下，成员到位后不再原地刷 `work_rate`，而是驱动 `behaviors.make_behavior` 对应状态机，行为目标点经 `nav.plan` 做 A* 绕障后逐拍跟随（复用 `behavior_runtime.BehaviorRunner`）。
- **进度/完成映射**：`behaviors.py` 给 5 个行为类加了 `progress_frac()`（圈数占比/阶段/覆盖率/换班次数），把行为推进映射回 coordinator 能消费的 progress；行为 `done` 即作业 `succeeded`。
- **行为事件通道**：行为细分事件（checkpoint_visited/cycle_completed/intrusion_detected/intercepted/handover_complete 等）走独立审计通道 `behavior_event`（`mock_fleet.behavior_events` → simulate 层 drain → `core.audit`），不进 coordinator 的 feedback 校验；`trajectory_v2.EVENT_NAME`/`BEHAVIOR_EVENT_NAME` 提供中文名，工作台时间轴与 `trajectory.html` 展示。
- **三个必须处理的耦合**（都踩过）：
  1. 行为时长远超 work 量（巡逻 3 圈≈72 步 vs work=12），planner 的 `dur` 用 `BEHAVIOR_DURATION` 经验表预估，否则超时/偏差误杀。
  2. 行为能耗与 work 线性模型解耦：planner 续航预估只算 travel×move_cost（行为移动耗电运行时按实际位移记），否则"时长×work_cost"放大 5-10 倍误拒下发。
  3. coordinator 的 `_dispatch` 窗口 deadline、`_deviation`、`_timeout_cancels` 在行为模式下跳过（行为层自带 max_steps/圈数兜底），时间窗只作排程参考。
- **两个 bug 修复**：① 行为事件收集计数器不能是 MockFleet 全局的（多 job 并发互相覆盖导致事件重复，改成 per-job 的 `job["bh_seen_events"]`）；② `AssaultBehavior` 的 staging/objective 点原来只 `nearest_free` 保证点 free，不保证从 site 直连，警察局（13m 主楼）西侧的点让平台卡墙角——加 `_reachable_ring_point` 沿径向回缩 + clearance 过小时退回 site。
- **验证**：`simulate(simple_city, motion=real, avoid=True, behavior=True)` 6/6 完成、settled，simulated_until≈187；6 作业全部走行为完成（patrol_cycles_done×2 / intercept_handled / map_shared / result_confirmed / relief_cycles_done），不再是 timeout 兜底。83 项测试全过。
- **工作台**：`validate_config` 加 `behavior`（默认 True，motion/avoid 不满足时**自动降级**而非报错，对齐 simulate 内部）；`run_worker` 透传；前端 `index.html` 加复选框、`app.js` 加 `behaviorEvents` 映射 + 事件细分名展示。产物 `outputs/workbench_behavior_20261028/`（6/6，165 条行为事件）。
- README_v2 已更新（工作台新建演示、`--behavior` 运行命令、参数表、"执行器两种口径"段落、mock_fleet 职责）。

### 关键经验（可复用）

- **消息替身接行为层的正确姿势**：行为层（`behaviors.py`）是纯决策、`city_nav.py` 是纯几何，都不持有 Coordinator/Job 引用，所以可以直接在 MockFleet 内部构造 Behavior（替身"自己掌握底层状态"的纪律不破）。行为事件走独立审计通道，不硬塞进 PROTOCOL_V2 的 status 语义。
- **行为模式的三个"解耦"**（时长/能耗/超时偏差）是本轮的核心设计，别在"行为时长 vs work 量"上硬对齐，而是让行为完成判定自成一套、规划期只做宽松预估。
- assault 卡墙角的根因是"staging 点 nearest_free 只保点 free、不保路径可达"，这跟 taskalloc 环境"能力约束必须在采样前施加"是同一类教训的几何版。

## planning_middle_demo：行为结构可视化 + 工作台端口坑（2026-10-28 晚）

用户反馈"看不到五类任务的具体运动"——数据里其实有（rover_03 巡逻绕 3 圈、rover_32 侦察展开），但整城地图尺度下巡逻环半径仅 2.4、只画轨迹线不画动作结构，肉眼看不出"在巡逻/封控"。补充：

- **行为结构带出**：`mock_fleet._behavior_structure()` 在 `_ensure_behavior` 构造行为后，把静态几何（patrol→loop 环、blockade→posts/intruder_start/ring_radius、recon→area_radius/sensor_radius、assault→staging/objective、hold→posts/standbys）以 `behavior_structure` 事件发出。
- **数据组装**：`trajectory_v2.build_replay_data` 收集 `behavior_structure`，输出 `behaviors` 数组（也带 `behavior` 标志）；`trajectory_player.html` 加 `behaviors-map` 层 + `drawBehaviors()` 画虚线结构（右下角"行为结构：开/关"），工作台 `app.js` 的 canvas draw() 里同步画。
- **顺手修掉**：`trajectory_player.html` 顶部过时说明"尚未实现五类任务执行行为"改成正确口径。
- **工作台端口坑**：用户重启工作台报"端口已被占用"——因为之前 `workbench_server.py --open` 启动的 python 进程（旧代码）还占着 8766。改完代码后必须 **taskkill 掉旧进程再重启**，否则浏览器刷新拿不到服务端新返回（load_run 的 behaviors 是旧进程内存里的旧 `trajectory_v2`）。诊断：`netstat -ano | grep 8766` → `taskkill //PID <pid> //F`。
- **遗留待用户定夺**：行为动作是真实城市尺度（巡逻半径 2.4≈7m、警察局主楼 13m），在 40×30 整图上偏小。两个方向：① 放大行为尺度（偏离真实尺寸）；② 加"点击作业点聚焦放大"局部视图。用户暂未选，先看虚线结构版。
